พื้นฐาน MIPS

คิดว่า CPU มี “ลิ้นชักเล็ก ๆ” สำหรับเก็บตัวเลขที่กำลังใช้งานอยู่ ลิ้นชักเหล่านี้เรียกว่า Register

Register คืออะไร?

เป็นที่เก็บข้อมูลขนาดเล็กและเร็วมากใน CPU เช่น $t0 สำหรับค่าชั่วคราว และ $s0 สำหรับค่าที่อยากเก็บไว้

คำสั่งคำนวณ

add บวก, sub ลบ, addi บวกตัวเลขคงที่

addi $t0, $zero, 5
→ ใส่เลข 5 ลงใน $t0

คำสั่งอ่าน/ตัดสินใจ

lw อ่านข้อมูลจากความจำ, sw เขียนข้อมูลลงความจำ, beq เลือกกระโดดเมื่อค่าเท่ากัน

แหล่งอ้างอิง: COA Notes 2014, บทที่ 2 - MIPS registers และคำสั่งพื้นฐาน

Pipeline Hazards

บางครั้งสายพานเร็วเกินไปจนคำสั่งถัดไปต้องการข้อมูลที่คำสั่งก่อนหน้ายังทำไม่เสร็จ นี่คือ Hazard

Structural Hazard

ฮาร์ดแวร์ชิ้นเดียวถูกใช้พร้อมกัน 2 stage เช่น IF อ่านคำสั่งขณะที่ lw อ่านข้อมูลจาก memory ก้อนเดียวกัน

แก้: แยก Instruction Memory
กับ Data Memory (เกมนี้แยกไว้แล้ว)

Data Hazard

คำสั่งใหม่รีบใช้ผลลัพธ์เก่า เช่น add เพิ่งคำนวณ แต่คำสั่งถัดไปอยากอ่านผลทันที

แก้: Forwarding ส่งผลลัพธ์ผ่านทางลัด
หรือ NOP รอ 1–2 รอบ จนผลถูกเขียนกลับ

Control Hazard

beq / j ตัดสินที่ ID ระหว่างนั้น CPU เดาว่า "ไม่กระโดด" (Predict Not Taken) แล้วหยิบคำสั่งถัดไปมาก่อน

ถ้าเดาผิด: ล้างคำสั่งผิดทาง (flush)
1 คำสั่ง เสีย 1 รอบ

ภารกิจของคุณ

มอง Hazard สีแดง เปิด Forwarding สำหรับการคำนวณ และใส่ NOP เมื่อต้องรอข้อมูลจาก lw หรือเมื่อ beq ใช้ค่าจากคำสั่งที่อยู่ติดกัน (เทียบที่ ID เร็วกว่า EX จึงต้องรอแม้มีสายลัด)
